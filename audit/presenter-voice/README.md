# Sawti 3.1.0 presenter voice and character — Mac commissioning required

## Confirmed studio wiring and scope

The operator confirmed: Scarlett 18i8 3rd Generation over USB-C, Genelec control-room speakers on physical outputs 1–2, presenter feed on physical outputs 3–4, and **Playback 3–4** selected as that presenter feed's source in Focusrite Control. These are operator reports, not a cloud observation of the device. Input 4 remains talkback; input numbers and USB output-channel numbers are separate.

Sawti's new output is bound to this exact Playback 3–4 assignment. The two-channel stream uses CoreAudio's hardware-sized channel map `[-1, -1, 0, 1, -1, …]`: other hardware outputs are unassigned, rather than receiving an array of silent samples. It uses the exact observed Scarlett UID/index and current verified rate, disables device-parameter changes, and has no system-speaker, default-device, aggregate, BlackHole or browser-speech fallback. A missing/ambiguous device, unknown rate, changed index/rate, unsupported map or output failure mutes speech. Source speech is resampled in memory; Sawti does not set the Scarlett clock.

This mapping limits Sawti's output request. It cannot prove that a Focusrite custom mix, driver loopback, system-audio tap, Audition track or Zoom capture excludes that bus. It also cannot stop a headset being picked up acoustically by a microphone. “Never recorded” cannot be guaranteed by software alone. Do not use spoken replies in production until the actual test recordings and headphone/mic placement have been checked.

## What is implemented

- An original inline SVG character: golden microphone, large glasses, blue eyes, curly hair, red lipstick and a stand. A caption welcomes the operator at page launch. Eyes blink and the head moves subtly; mouth animation follows backend speaking state, polled at 150 ms while preparing/playing. This is a speaking indicator, not phoneme-level lip sync. Reduced-motion settings are respected.
- Explicit choice of installed macOS English voice and optional Arabic voice. Select the desired female voice from the installed list; gender/voice availability is not assumed. Missing language support falls back to text, never another output. Long replies are replaced by a short spoken cue to read the full instructions on screen.
- `/usr/bin/say` writes only to a temporary private AIFF/text directory; it never performs playback itself. The directory is removed on completion/cancellation. No spoken text, synthesized audio, voice name or device identity is added to learning reports. Abrupt machine/process death may leave a private temporary directory for OS cleanup.
- A single, bounded job with no stale-reply queue. Speech is limited to 700 characters/30 seconds, with conservative digital gain. Configuring does not play audio. Enabling speech requires a completed explicit test and all four operator attestations. Privacy remains operator-attested, never automatically verified.
- A spoken welcome after enabling for the current powered session, followed by spoken chat/tap-to-speak replies. No automatic audible greeting is sent merely because the app opens: its recording state and privacy cannot yet be established. OFF, mode changes, mic-plan changes, approved device changes, errors or Mute revoke the voice qualification. Re-enable requires testing again. Browser page close requests mute on a best-effort basis; OFF/Quit is authoritative.
- Private test admission is coordinated with Go Live/Record/pre-test. An unqualified test cannot overlap Sawti's live marker or sound check. While it is pending, Go Live and Record are blocked. No Audition or Zoom transport command is sent by this feature.
- “Is the audio good?” uses fresh, complete programme-level measurements and does not claim recording integrity. “Has recording started?” reports that recording is unconfirmed, even when LIVE is marked. The AI prompt and status tool also retain this distinction.

Always-listening Mic 1 commands, verified Audition transport/track assignment, autonomous countdown and automatic isolation verification are not implemented by this update. Existing voice input still uses the optional browser microphone button; commission the intended browser input separately. This speech path does not change its input selection.

## Guided setup on the Mac — no typed Terminal commands

1. Finish production recording, quit Sawti, extract 3.1.0 into a new permanent Documents folder and run **INSTALL_SAWTI.command**. Launch and refresh the page; verify version 3.1.0. The existing local AI models are unchanged.
2. Switch ON, choose the mode and confirm the Podcast microphones if applicable. Do this before voice commissioning: changing the mic plan invalidates voice qualification.
3. Under **Ask Sawti → Private headset voice setup**, click **Find Scarlett and installed voices**. Choose the exact Scarlett, **USB Playback 3–4 → presenter outputs 3–4**, and the installed English/optional Arabic voices. Confirm the actual mapping and save the session voice plan. No routing is loaded or changed.
4. Keep all production recording stopped and do not mark the show LIVE. Prepare isolated test takes **directly in Audition and, for Zoom mode, Zoom**, covering every intended recorded track and any loopback/system-audio capture, including Zoom Share Sound if used. Start these test takes manually in their applications; Sawti's Live/Record actions are deliberately blocked during the unqualified voice test.
5. Approve **Play private test phrase (idle)**. Only the presenter should hear the phrase; check Genelecs and the Zoom guest feed as well. Check comfortable headphone volume separately from software gain.
6. Stop those test takes manually and listen back to every programme/guest track and any Zoom recording. Verify no assistant voice is present, recording stayed continuous and existing monitoring had no dropout. Check physical headphone/microphone bleed at actual presentation volume and placement. If speech or any disruption appears, leave Sawti muted and diagnose while idle. Do not load presets or reset rates during a live session.
7. Only after a successful test, tick the four isolation checks and select **Enable spoken replies for this session**, confirming production is idle. Sawti then introduces herself over the tested headset bus. Ask “Is the audio good?” or “Has recording started?” using text or the existing voice button.
8. **Mute Sawti voice** stops only Sawti speech and revokes qualification. OFF/Quit cancels its native job too; neither sends Stop to Audition nor changes the production audio route. If any routing/capture setup changes outside Sawti, mute and repeat the tests; those external changes are not automatically observable.

## Validation and limits

Automated tests use substitute CoreAudio/output callbacks and a file-only synthesis process. They verify exact device/channel selection, no default fallback or device-parameter changes, rate conversion, mandatory commissioning, revocation, OFF cancellation before playback, no voice content in exported learning, and no false recording-state claim. A failed close prevents output reuse and PortAudio reinitialisation until restart.

The character preview is rasterised from the SVG source, not a screenshot of a qualified Mac app. Browser tests execute the actual UI JavaScript with DOM/media/network substitutes. A headless Chromium screenshot attempt was unsuccessful in this environment; no successful full-browser/Safari check is claimed. No physical Scarlett, macOS 27.0.1, installed Mac voice, headphones, Audition 26.3.0.79 or Zoom recording was available in the Linux cloud. Actual CoreAudio playback, additive monitoring, cancellation, isolation, voice quality and long-session operation remain Mac acceptance gates.
