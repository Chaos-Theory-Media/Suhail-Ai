# Sawti implementation roadmap

Build on source baseline `8818f84`; do not rebuild the working application. Preserve original files/behaviour in the baseline commit, and use small reviewable changes with regression checks. Effort estimates should follow Mac compatibility discovery, especially Audition state observability and optional speech packages.

| Order | Deliverable | Acceptance gate |
| --- | --- | --- |
| 1 — safety | Fix browser OFF gating, pending permission/capture cancellation and admitted-request races; protect local mutation endpoints; define owned-process shutdown and crash behaviour | Both browser audit checks and corresponding backend safety checks pass; no new stream/action starts after OFF; tests verify external processes are untouched |
| 2 — truthful observation | Connect health alerts; propagate freshness/errors and manual detail; align selected/captured modes; represent recording state as recording/idle/unknown; validate exact device/model identities and startup readiness | Stale/error/unknown states never show as verified readiness; model tag, health integration and status audit checks pass; never infer recording state merely from process presence |
| 3 — actual Mac adapters | Qualify Scarlett input capture and vendor software; investigate supported Audition/Zoom state APIs; resolve channel maps through guided calibration; expose capability limits explicitly | Operator-approved Mac session verifies actual channels, record state or explicit unknown, input permissions and guest return; no routing changes without scoped approval |
| 4 — supervised modes and recovery | Add an allowlisted action broker, approval bound to action/state, recording guard, audit trail, cancellation, precondition/postcondition checks and supervised rollback | Unit/integration tests cover denied, stale, concurrent and replayed approvals; prompt content cannot grant authority; unknown/active recording blocks disruptive automation unless specifically authorised |
| 5 — complete local AI and languages | Exact local Qwen3 selection/inference; managed cached STT, Arabic/English TTS and RTL text; bounded voice buffers; opt-in enrolment with calibrated unknown rejection, retention/deletion and local data protection | Fixed bilingual corpus and unknown-speaker tests meet agreed thresholds; all normal operations work offline after verified installation; recognition never grants control permissions |
| 6 — macOS product lifecycle | Keep useful UI; package signed/notarised desktop application, supply runtime, guide permissions and model setup, show diagnostics and one-click safe exit; provide upgrades/uninstall | Clean supported Apple Silicon Mac can install and use daily features without Terminal; no production audio configuration is changed during install/start/stop/uninstall |
| 7 — release qualification | Execute Mac integration matrix and recording continuity/soak tests, failure injection and recovery drills | Reproducible evidence on the named Mac Studio, Scarlett 18i8 3rd Gen, Audition, Zoom and BlackHole; required failures resolved and limitations visible in UI |

The initial interface remains diagnostic and read-only until the safety boundary is demonstrated. Routing control is not a prerequisite to delivering truthful monitoring and guidance. Retain deterministic help when local AI is unavailable; keep presenter identity separate from operator authorisation.

Required external input is access to the Mac Studio for validation and an explicitly approved non-production test session. No credentials or private audio samples should be entered into Git. This Linux cloud environment cannot substitute for macOS hardware validation.
